# 高级语言程序设计大作业实验报告

## 一、作业题目

**"豹豹大作战" —— 基于 Qt6 的物理弹射对战游戏**

本项目使用 C++ 和 Qt6 图形化框架开发了一款回合制物理弹射对战游戏。玩家通过拖拽方式发射己方角色（"豹豹"），利用物理碰撞机制撞击敌方角色，配合六种不同技能的豹豹类型，展开策略对决。先击败对方全部6条命的阵营获胜。

#### 4.1.2 游戏主循环

```
定时器(16ms ≈ 62.5fps)
    ↓
updatePhysics()
    ├── 第1步: 更新旋转动画 + 碰撞自转衰减
    ├── 第2步: 遍历运动中的豹豹
    │   ├── 边界碰撞检测（梯形区域 + 镜面反射）
    │   ├── 非线性缓动（四段式速度曲线）
    │   └── 位置更新 + 碰撞箱同步
    ├── 第3步: handleCollisions()
    │   ├── 15对圆形碰撞检测 (C(6,2))
    │   ├── 位置修正（推开重叠）
    │   ├── 伤害判定（仅移动方造成伤害）
    │   ├── 技能效果处理
    │   ├── 物理反弹（镜面反射 + 衰减）
    │   └── 死亡判定 + 复活
    ├── 第4步: 轮次切换判定
    │   └── 当前阵营全部停止 → 交换出手权 / 进入下一轮
    └── 第5步: 屏幕震动衰减 + 边界安全网 + 刷新显示
```

#### 4.1.3 轮次管理

| 规则 | 说明 |
|------|------|
| 初始顺序 | 红色方（右侧）先手 |
| 交替出手 | 当前阵营全部停止 → 交换 order 标志 |
| 进入下一轮 | 6个豹豹全部 `hasActed == true` → 重置状态，轮次+1 |
| 阵营标记 | `camp == order` 为当前行动方（红色轮廓），否则为等待方（蓝色轮廓） |

### 4.2 算法与公式

#### 4.2.1 拖拽发射系统（弹弓机制）

```
发射参数计算:
  dragDistance = min(rawDistance, maxDrag)
  ratio = dragDistance / maxDrag              // 拖拽力度 0~1
  speed = ratio × 20                          // 像素/帧（最大初速20）
  totalDistance = dragDistance² / 12.5        // 行动总距离

发射方向:
  launchDir = -dragVector.normalized()        // 拖拽反向 = 发射正向（弹弓原理）
  velocityF = launchDir × speed
```

**死区设计**: 最小拖拽距离 40px，防止误触发射。

#### 4.2.2 四段非线性缓动函数

模拟"爆发→匀速→缓停"的运动手感：

| 阶段 | 进度区间 | 倍率 | 效果 |
|------|---------|------|------|
| 爆发段 | [0, 15%] | 2.5 倍 | 快速起步，模拟弹射初加速度 |
| 过渡段 | [15%, 40%] | 线性 2.5→1.0 | 平滑过渡到匀速 |
| 匀速段 | [40%, 70%] | 1.0 倍 | 稳定巡航 |
| 缓停段 | [70%, 100%] | 二次衰减 1.0→0.15 | 逐渐减速停下 |

```cpp
// 核心实现
qreal getEasingMultiplier(qreal t) {
    if (t < 0.15) return 2.5;
    if (t < 0.4)  return 3.4 - 6.0 * t;
    if (t < 0.7)  return 1.0;
    qreal local = (t - 0.7) * 3.33333333333333;
    return 1.0 - 0.85 * local * local;
}
```

#### 4.2.3 圆形碰撞检测

```
检测条件: distance(centerA, centerB) < 60.0    // 半径之和(30+30)
```

```cpp
QPointF delta = baoA.center - baoB.center;
qreal distance = std::sqrt(delta.x()² + delta.y()²);
qreal minDistance = 60.0;  // 两个30半径豹豹的最小距离
if (distance < minDistance) { /* 碰撞处理 */ }
```

#### 4.2.4 镜面反射物理

```
反射公式: v' = v - 2(v·n)n

其中:
  n = 碰撞法线（从B指向A的单位向量）
  vn = v·n  (法线分量)
  vt = v·t  (切线分量)

反射后: v' = tangent × vt - normal × vn

主动方衰减:
  velocityF   *= 0.85    // 速度衰减15%
  remainingDistance *= 0.9  // 行动距离衰减10%

被动方弹开（静止→被动移动）:
  passive.velocityF = -activeDirection × (activeSpeed × 0.30)
  passive.remainingDistance = active.remainingDistance × 0.30
```

#### 4.2.5 梯形边界碰撞系统

预计算优化——在构造函数中一次性计算四条边的内侧法线和边长倒数，避免每帧 `std::hypot` 调用：

```cpp
// 初始化的预计算
for (int e = 0; e < 4; e++) {
    QPointF edgeDir = m_boundaryVerts[(e+1)%4] - m_boundaryVerts[e];
    qreal len = std::hypot(edgeDir.x(), edgeDir.y());
    m_boundaryInvLen[e] = 1.0 / len;
    // 顺时针 → 内侧法线 = (-edgeDir.y, edgeDir.x) 归一化
    m_boundaryInNormals[e] = QPointF(-edgeDir.y() * invLen, edgeDir.x() * invLen);
}
```

边界安全网 `clampAllToBoundary()`: 每帧将有符号距离 < 30 的圆心沿法线推出，防止飞出/卡死。

#### 4.2.6 拖拽预览射线追踪

```
calculateReflectionPath(start, direction, maxLength):
  points = [start]
  currentPos = start
  currentDir = direction
  
  for each reflection (max 2段):
    找最近碰撞点: min(边界交点, 豹豹交点)
    if 无碰撞: 追加终点 → 结束
    追加碰撞点 → 更新方向为反射方向 → 继续
```

用于在拖拽时显示带反射的预测弹道（白色预览线）。

#### 4.2.7 屏幕震动

```cpp
// 碰撞强度正比于相对速度
triggerShake(min(relSpeed * 0.8, 15.0), 6);  // 强度上限15, 持续6帧

// 每帧衰减
m_shakeOffset = QPointF(random(-1,1) * intensity, random(-1,1) * intensity);
intensity *= decay;
```

### 4.4 音效系统

```
┌─────────┐  emit requestCollisionSound()
│ 主线程   │ ─────────(QueuedConnection)────────→ ┌──────────────┐
│GameWidget│                                       │  音频线程    │
│         │ ←─── setMuted(bool) ──── MainWindow    │SoundPlayer   │
```

## 六、收获

### 6.1 Qt 信号槽机制与多页面导航

使用 `QStackedWidget` + 信号槽实现了4个页面的无感切换，关键模式：

```cpp
// 模式1: 简单跳转
connect(startPage, &StartWidget::goToSelectWidget, [stack](){
    stack->setCurrentIndex(1);
});

// 模式2: 携带数据传递
connect(selectPage, &SelectWidget::goToGameWidget, [this, stack](){
    QList<BaoBaoType> p1Types = selectPage->getP1SelectedTypes();
    QList<BaoBaoType> p2Types = selectPage->getP2SelectedTypes();
    gamePage->setSelectedTypes(p1Types, p2Types);
    stack->setCurrentIndex(2);
});

// 模式3: 跨线程信号
connect(this, &GameWidget::requestCollisionSound,
        m_soundPlayer, &CollisionSoundPlayer::play,
        Qt::QueuedConnection);
```

**收获**: 理解了 Qt 元对象系统的核心价值——松耦合的对象间通信。emit 信号的对象不需要知道 slot 的接收者是谁，极大地降低了代码耦合度。

### 6.2 物理模拟与边界处理

物理系统的难点在于：
1. **浮点精度**: 使用 `QPointF`（qreal 双精度）存储圆心坐标，碰撞箱通过 `moveCenter()` 推导，避免整数截断累积误差。
2. **预计算优化**: 梯形边界的法线和边长倒数在构造函数中一次性计算，每帧碰撞检测直接使用，避免重复 `std::hypot` 调用。
3. **边界安全网**: 仅靠反弹检测不够——碰撞推开可能将豹豹挤出梯形区域。`clampAllToBoundary()` 每帧强制钳制所有圆心，作为最后防线。

**收获**: 物理模拟中，"安全网"机制至关重要——不能仅依赖事件驱动的碰撞检测，必须有逐帧校验的兜底逻辑。

### 6.3 多线程音效系统

MCI 音效播放如果放在主线程会阻塞 UI（`mciSendString` 是同步调用）。解决方案：

1. 创建独立 `QThread`，将 `CollisionSoundPlayer` `moveToThread()` 到音频线程
2. 主线程 `emit requestCollisionSound()` → `Qt::QueuedConnection` 跨线程传递
3. MCI 4通道（`cs_0~cs_3`）轮转，确保多次碰撞音效不互相覆盖
4. 线程结束时 `deleteLater` 自动清理，无内存泄漏

**收获**: 理解了 Qt 的线程模型——不能直接跨线程调用 slot，必须通过信号 + QueuedConnection。这是 Qt 多线程编程的核心原则。

### 6.4 资源管理与跨平台部署

起初使用硬编码路径 `D:\MyCode\...`，导致 Release 版本在其他电脑上无法加载图片。改造过程：

1. **qrc 资源系统**: 将所有图片注册到 `res.qrc`，编译时嵌入可执行文件
2. **运行时路径解析**: 音效文件（MCI 需要真实文件系统路径）使用 `QCoreApplication::applicationDirPath()` 动态定位，支持开发/Release 两种目录结构
3. **验证工具**: 使用 `QFile::exists()` 检测文件存在性，`QDir::cdUp()` 回退查找

**收获**: 硬编码绝对路径是跨平台部署的大忌。Qt 的 qrc 资源系统 + `applicationDirPath()` 是标准解决方案。

### 6.5 虚析构函数的必要性

`CollisionSoundPlayer` 作为独立 QObject 驻留在音频线程中，其析构必须通过 `deleteLater()` + 线程 `finished` 信号的组合来确保线程安全：

```cpp
connect(m_soundThread, &QThread::finished,
        m_soundPlayer, &QObject::deleteLater);
connect(m_soundThread, &QThread::finished,
        m_soundThread, &QObject::deleteLater);
```

如果直接在 `~GameWidget()` 中 `delete m_soundPlayer`，会在主线程尝试析构一个仍在另一线程运行的对象，导致 `"thread destroyed while running"` 错误。必须先 `quit()` → `wait(3000)` → 让线程自然结束 → `finished` 信号触发自动清理。
